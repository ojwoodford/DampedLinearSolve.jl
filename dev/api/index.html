DampedLinearSolve — Module
DampedLinearSolve

Solve, without allocating, the damped linear problems a second-order optimizer poses, (H + λD) x = −g and min ‖J x + r‖² + λ‖x‖²_D, and report the outcome well enough for the optimizer to decide what to do next. It applies the damping it is given and never chooses it.

The contract a linear system meets is in the documentation ("The linear-system contract"); the systems for SMatrix, Matrix and SparseMatrixCSC Hessians and Jacobians are built by makehessiansystem and makejacobiansystem, and check_linear_system checks an implementation.

Systems and their construction

DampedLinearSolve.AbstractLinearSystem — Type
AbstractLinearSystem

Supertype of the linear systems: a symmetric matrix A, a vector b and a solution x of dimension n, and a damping to apply when solving. The built-in systems are built by makehessiansystem (static, dense and sparse A) and makejacobiansystem (A = JᵀJ held as a Jacobian J and a residual r, dense, sparse or static). A new system type implements the functions of the contract below, as methods of DampedLinearSolve's functions, and should pass check_linear_system. The documentation's "The linear-system contract" page states each rule.

DampedLinearSolve.makehessiansystem — Function
makehessiansystem(H, linsolver) -> AbstractLinearSystem
makehessiansystem(n, linsolver) -> AbstractLinearSystem

A linear system built from a Hessian prototype H, whose A is stored as H describes, or, without a prototype, a system of n variables: static (StaticArrays, stack allocated) when n is a Static.StaticInt, dense when it is an Int.

  • H::MMatrix: a static system that writes into H; any other StaticMatrix: a static system of its own.
  • H::Matrix: a dense system that writes into H; any other AbstractMatrix: a dense system on a copy of the same element type.
  • H::SparseMatrixCSC: a sparse system that writes into H, or into a copy with explicit zeros added if a diagonal entry is missing.

The element type of H, Float64 or Float32, is the system's (systemeltype): A and its factorization are held in it, while b, x, the damping and the queries are Float64. Any other element type is an ArgumentError, as is a linsolver that does not offer Float32 for that kind of system (see the contract's "Precision"). Without a prototype the system is Float64. The dense and sparse systems are conditioned inside the solve (the contract's "Conditioning"); the static system is not.

A package that implements the contract adds methods for its own prototypes. linsolver (a Symbol or a StaticSymbol) is used to preallocate the solver's workspace, and the system must be solved with it. Validate H first with checkhessian.

Example

ls = makehessiansystem(zeros(3, 3), :ldl)      # dense, Bunch–Kaufman workspace preallocated
ls = makehessiansystem(static(2), :auto)        # static 2 × 2
DampedLinearSolve.makejacobiansystem — Function
makejacobiansystem(J, n, linsolver) -> AbstractLinearSystem

A Jacobian linear system built from a Jacobian prototype J, for n variables: A = JᵀJ held as J and the residual r (getJ, getr), b = Jᵀr, and each solve the solution of min ‖J x − r‖² + λ xᵀD x from J, without forming JᵀJ unless linsolver is :cholesky or :ldl.

  • J::Matrix: a dense system that writes into J (with the values it holds); static (StaticArrays) when n is a Static.StaticInt, linsolver is QR (:auto or :qr) and m·n is small.
  • J::Integer: the same, for m = J residuals, with its own J starting as zeros.
  • J::SparseMatrixCSC{T, Int}: a sparse system, solved by SuiteSparse's SPQR, its symbolic analysis done here, once.

The element type of a matrix J, Float64 or Float32, is the system's (systemeltype): J, its reductions and factorizations are held in it, while r, b, x and the queries are Float64 (an integer m gives a Float64 system). Any other element type is an ArgumentError, as is a linsolver that does not offer Float32 for the system: SPQR, for one (see the contract's "Precision"). The dense and sparse systems are conditioned inside the solve; the static one is not.

linsolver is :auto or :qr (QR of J), or :lsmr with Krylov.jl loaded. For a dense J (a Matrix or an integer m) it can also be :cholesky or :ldl: the normal equations, JᵀJ formed once per linearization (BLAS syrk) and JᵀJ + λD factored per damping by Cholesky or Bunch–Kaufman; always the dense system, never the static one, whatever n. They square the condition number of J, so :auto is QR (see DenseJacobianLinearSystem for costs). Validate J first with checkjacobian and check_jacobian_linsolver.

Example

ls = makejacobiansystem(20, 3, :auto)     # 20 residuals, 3 variables, dense
DampedLinearSolve.structurekey — Function
structurekey(P)

A value equal for two prototypes from which systems of the same structure are built (for a matrix, its type and size), for a caller that caches systems. A package with its own prototype type adds a method.

DampedLinearSolve.checkhessian — Function
checkhessian(H, n::Integer) -> nothing

Throws, before anything is built, if H cannot be the Hessian prototype of a system of n variables: a DimensionMismatch for a matrix that is not n × n. H = nothing (no prototype) passes.

DampedLinearSolve.checkjacobian — Function
checkjacobian(J) -> nothing

Throws an ArgumentError if J is not a Jacobian prototype a Jacobian system can be built from: a Matrix or SparseMatrixCSC{T, Int} with T = Float64 or Float32 and at least one row, or an integer number of residuals m ≥ 1 (or a prototype a package that implements the contract adds). Whether the solver offers Float32 is checked when the system is built.

DampedLinearSolve.check_jacobian_linsolver — Function
check_jacobian_linsolver(J, linsolver::Symbol) -> nothing

Throws an ArgumentError if the Jacobian system of the Jacobian prototype J does not take linsolver. The built-in prototypes take :auto, :qr and :lsmr (the last with Krylov.jl loaded, which checklinsolver checks); a dense one (a Matrix or an integer m) also takes :cholesky and :ldl (the normal equations), and a SparseMatrixCSC one does not.

DampedLinearSolve.jacobian_ncols — Function
jacobian_ncols(J) -> Union{Int, Nothing}

The number of columns of the Jacobian prototype J (the number of variables of its system), or nothing for an integer m, whose system is sized by the n passed to makejacobiansystem.

DampedLinearSolve.jacobian_nrows — Function
jacobian_nrows(J) -> Int

The number of residuals the Jacobian prototype J stands for: m for an integer, the number of rows of a matrix.

DampedLinearSolve.checklinsolver — Function
checklinsolver(linsolver) -> true

Returns true if a solver of that name is available, and otherwise throws an ArgumentError that says which package provides it (:cg, :minres and :lsmr: Krylov.jl; :pardiso: Pardiso.jl), or that the name is unknown. linsolver is a Symbol or a StaticSymbol.

DampedLinearSolve.validatelinsolver — Function
validatelinsolver(linsolver::Union{Symbol, StaticSymbol}) -> Bool

Returns true if linsolver names a solver of a loaded package, false otherwise. The built-in solvers are :auto, :cholesky, :ldl and :qr; loading Krylov.jl adds :cg, :minres and :lsmr, and loading Pardiso.jl adds :pardiso.

Filling

DampedLinearSolve.getA — Function
getA(ls)

The storage of the system's matrix A: a Matrix, an MMatrix, a SparseMatrixCSC, or a storage type of the system's own (for a Jacobian system, one holding J and r: see getJ).

DampedLinearSolve.getb — Function
getb(ls) -> AbstractVector

The system's right-hand side b, of length n. For a Jacobian system it is Jᵀr, formed by gradient!.

DampedLinearSolve.getx — Function
getx(ls) -> AbstractVector

The vector solve! writes the solution into, of length n.

DampedLinearSolve.zero! — Function
zero!(ls)

Prepares the system for a fresh fill, keeping its structure (pattern, workspaces): zeroes b and any storage that is accumulated into (A of a Hessian system), and invalidates everything computed from the previous fill. A Jacobian system's J and r are set by the fill, not accumulated, so they are not zeroed; their factorization and column norms are invalidated.

Example

ls = makehessiansystem(3, :auto)
zero!(ls)
DampedLinearSolve.getJ — Function
getJ(A)

The Jacobian J in the storage A = getA(ls) of a Jacobian system, which the caller writes (it is set, not accumulated). After writing it and getr(A), call gradient! and markstale!.

DampedLinearSolve.getr — Function
getr(A)

The residual r in the storage A = getA(ls) of a Jacobian system, which the caller writes.

DampedLinearSolve.gradient! — Function
gradient!(b, A) -> b

Writes b = Jᵀr from the Jacobian storage A's current J and r (call it with b = getb(ls)). For a sparse J it first checks that the pattern is the one the system was built for, and throws an ArgumentError if an entry was added.

DampedLinearSolve.markstale! — Function
markstale!(A) -> A

Marks the Jacobian storage A's factorization and column norms as out of date. Call it after writing J or r and before the next solve or query.

Damping and solving

DampedLinearSolve.dampen! — Function
dampen!(ls, λ)
dampen!(ls, λ, s)

Records the damping λI, or λ·Diagonal(s) with s in the units of the diagonal of A (for a Jacobian system, of JᵀJ), not squared. The damping is applied only inside solve!; A is left as it was filled. Each call replaces the damping set before, scaling included; dampen!(ls, λ, nothing) is dampen!(ls, λ), and λ = 0 is undamped.

DampedLinearSolve.solve! — Function
solve!(ls, linsolver = static(:auto)) -> SolveStatus

Solves the damped system (A + λD) x = b into getx(ls) with the solver linsolver (a Symbol or a StaticSymbol, the one the system was built for) and returns a SolveStatus. A and b are left exactly as they were filled, whether the solve succeeds or fails.

Solvers

  • :auto (Cholesky for a static or dense A, LDLᵀ for a sparse one, QR of J for a Jacobian system), :cholesky, :ldl (Bunch–Kaufman for a dense A, LDLᵀ for a sparse one) and :qr.
  • With Krylov.jl loaded: :cg and :minres (dense and sparse A; Jacobi preconditioned on a sparse A whenever the damped diagonal is positive) and :lsmr (a Jacobian system, on J).
  • With Pardiso.jl loaded: :pardiso (sparse, and dense through a sparse copy).

On a static system, :qr is an LU solve (StaticArrays has no pivoted QR), and :ldl uses Cholesky, falling back to LU when the matrix is not positive definite (the solve is then reported as Indefinite).

Example

ls = makehessiansystem([2.0 0.0; 0.0 4.0], :auto)
getb(ls) .= [4.0, 8.0]
solve!(ls, :cholesky)   # Success; getx(ls) == [2.0, 2.0]
DampedLinearSolve.SolveStatus — Type
SolveStatus

Enum returned by solve!:

  • Success: x solves the damped system, and is finite.
  • NotPositiveDefinite: the factorization failed, or the solution is not finite: the damped matrix is not positive definite, singular to working precision, or not finite. x is unspecified.
  • Indefinite: the solve completed but found the damped matrix indefinite (:ldl from its pivots, :cg from nonpositive curvature). x solves the damped system, as for Success, but is not a descent direction to rely on.
DampedLinearSolve.Success — Constant
Success

SolveStatus indicating that the linear system was solved successfully.

DampedLinearSolve.NotPositiveDefinite — Constant
NotPositiveDefinite

SolveStatus indicating that the factorization failed (for example a non-positive pivot in Cholesky) or that the solution is not finite.

DampedLinearSolve.Indefinite — Constant
Indefinite

SolveStatus indicating that the matrix was found indefinite, or negative curvature was encountered, by a solve that completed: x solves the damped system, but is not a descent direction to rely on. An implementation of the contract that returns Indefinite must leave the whole of x solved, not part of it.

Queries on the undamped system

DampedLinearSolve.max_diag — Function
max_diag(ls)

The largest absolute diagonal entry of the undamped A (for a Jacobian system, the largest squared column norm of J); NaN if a diagonal entry is NaN.

DampedLinearSolve.getdiag! — Function
getdiag!(d, ls) -> d

Writes the diagonal of the undamped A into d (for a Jacobian system, the squared column norms of J) and returns d. For building a Marquardt scaling.

DampedLinearSolve.quadform — Function
quadform(A, v)

The quadratic form vᵀ A v of the storage A = getA(ls) (for a Jacobian system, ‖J v‖²), with single-threaded loops for Matrix, StaticArray and SparseMatrixCSC; any other storage falls back to LinearAlgebra.dot(v, A, v).

DampedLinearSolve.quadratic_model_change — Function
quadratic_model_change(ls, dx)

dxᵀ A dx / 2 + bᵀ dx for the undamped system: the change in the quadratic model for a step dx when b is the gradient (negative for a descent step).

DampedLinearSolve.dampingfloor — Function
dampingfloor(ls) -> Float64

The smallest damping the system's solver resolves, relative to the diagonal: eps(T) for a factorization of A + λD, including a dense Jacobian system built for :cholesky or :ldl (which factors JᵀJ + λD), and eps(T)^2 for a Jacobian system solved by QR of J (or LSMR), which works with the condition number of J. T is the system's element type (systemeltype); the value is a Float64 either way.

DampedLinearSolve.isfinitesystem — Function
isfinitesystem(ls) -> Bool

Whether every stored value of A (for a Jacobian system, of J and r) is finite. Damping cannot repair a non-finite matrix.

DampedLinearSolve.systemeltype — Function
systemeltype(ls) -> Type

The element type of the linear system: the type its matrix (A, or J of a Jacobian system) and every copy, reduction and factorization of it are held in, Float64 or Float32. It is the element type of the prototype the system was built from (Float64 for a system built from a number of variables or residuals). b, x, r, the damping and every query's result are Float64 whatever it is. An optimizer reads it to set the tolerances that depend on the precision of the matrix, such as its damping floor. A system of another package that does not implement it is taken to be Float64.

The spare system

DampedLinearSolve.copy_structure — Function
copy_structure(ls)

A system of the same structure with its own A and b (contents unspecified; a Jacobian system's copy starts with the same J), for a trial point. It may share x and solver workspaces with ls; filling and solving one never changes the other's next solution.

DampedLinearSolve.sharex — Function
sharex(ls, from)

ls, or a copy of it sharing its A and b, whose getx is getx(from).

Conformance

DampedLinearSolve.check_linear_system — Function
check_linear_system(make_ls; n, linsolvers, rtol = 1e-8)

Check that the linear systems built by make_ls meet the AbstractLinearSystem interface, for each solver in linsolvers (symbols such as :auto, :cholesky, :ldl). Throws an ErrorException naming the first rule that is broken; returns nothing otherwise.

make_ls(linsolver) (or make_ls(), if that is the only method) must return a fresh system of dimension n whose Hessian storage can hold a dense symmetric matrix wherever its pattern allows. The test matrices are built inside that pattern and made diagonally dominant, so they are positive definite. Reading and writing the storage uses conformance_matrix, conformance_fill! and conformance_fillb!, which have methods for Matrix, MMatrix, SparseMatrixCSC and the storage of the Jacobian systems (and, from a package that implements the contract, its own storage); conformance_traits says what the storage can represent. For the Jacobian storage, JᵀJ is compared with the test matrix to a relative 1e-10 (then exactly with itself), the indefinite-A checks are skipped, and when m < n the test matrix has rank m, the undamped solve must not return Success, and the solves that are otherwise undamped use a damping of 0.25. Solutions are compared with rtol; use a looser value for iterative solvers. rtol and the round trip's 1e-10 are stated for a Float64 system: a system of element type T (systemeltype) is held to them times eps(T)/eps(Float64), and an exact storage's round trip gives the test matrix rounded to T.

The rules, for each solver:

  • getA, getb, getx have dimension n.
  • solve! returns Success for a positive-definite system and solves A * x = b into getx (an optimizer negates it to get the step), leaving A and b exactly as they were written: undamped, damped, and also when the solve fails.
  • dampen!(ls, λ) solves (A + λI) x = b; dampen!(ls, λ, s) solves (A + λ Diagonal(s)) x = b; each replaces the damping set before, so returning to an earlier damping gives the identical x.
  • copy_structure(ls) has its own A and b: filling and solving it changes neither the original's A and b nor the original's next solution.
  • sharex(trial, ls) returns a system whose getx is getx(ls).
  • quadform(getA(ls), v) ≈ v' A v (so getA(ls) supports dot(v, A, v), or has a quadform method), and quadratic_model_change(ls, v) ≈ v' A v / 2 + b' v.
  • max_diag(ls) is the largest absolute diagonal entry of A, and NaN if a diagonal entry is.
  • dampingfloor(ls) is in (0, 1e-6], and a positive-definite A damped by dampingfloor(ls) * max_diag(ls) solves.
  • zero!(ls) zeroes A (unless the storage is not accumulated into: see conformance_traits) and b, and the system can be refilled and solved afterwards, without reusing a factorization from before zero!.
  • For an indefinite A, :cholesky does not return Success and :ldl returns Indefinite (checked only for the solvers in linsolvers).

Example

check_linear_system(s -> makehessiansystem(zeros(5, 5), s); n = 5, linsolvers = (:auto, :cholesky, :ldl, :qr))
check_linear_system(s -> makejacobiansystem(8, 5, s); n = 5, linsolvers = (:auto, :qr))
DampedLinearSolve.conformance_matrix — Function
conformance_matrix(A) -> Matrix{Float64}

The matrix that the Hessian storage A (as returned by getA) represents, as a dense Matrix. Used by check_linear_system; a new kind of Hessian storage needs a method.

DampedLinearSolve.conformance_fill! — Function
conformance_fill!(A, M) -> A

Write the entries of the dense matrix M into the Hessian storage A, wherever A can hold a value (every entry of a dense matrix, the stored entries of a sparse one); other entries of M are ignored. Used by check_linear_system; a new kind of Hessian storage needs a method.

DampedLinearSolve.conformance_fillb! — Function
conformance_fillb!(ls, b) -> ls

Write the right-hand side b into the linear system ls, after its Hessian storage has been filled with conformance_fill!. The default sets getb(ls) .= b; a system whose b is derived from other storage (as b = Jᵀr for a Jacobian system) needs a method that also fills that storage. Used by check_linear_system.

DampedLinearSolve.conformance_traits — Function
conformance_traits(A) -> (; exact, maxrank, indefinite)

What check_linear_system can expect of the Hessian storage A:

  • exact: whether conformance_fill! followed by conformance_matrix gives the matrix back exactly; otherwise to a relative 1e-10 (as for JᵀJ built from a factor).
  • maxrank: the largest rank of matrix the storage can hold; below n, the checker uses a dense positive semidefinite test matrix of that rank, a right-hand side in its range, and a positive base damping where it would otherwise solve undamped, and checks that an undamped solve does not return Success.
  • indefinite: whether the storage can hold an indefinite matrix; if not, the indefinite-A checks are skipped.
  • accumulates: whether fdf! accumulates into the storage, so that zero! must zero it. If not (a Jacobian, whose entries resjac! sets), the "zero! zeroes A" check is skipped, and the system is instead refilled with a different matrix after zero!, to check that zero! invalidated any cached factorization.

The default, (exact = true, maxrank = typemax(Int), indefinite = true, accumulates = true), fits every square storage. A method returning a tuple without accumulates counts as true.
